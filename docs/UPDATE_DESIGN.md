# llama.cpp 更新系统设计

> 更新的是 **llama.cpp 运行程序**，不是 GGUF 模型（本应用不下载模型）。

## 1. 版本源

- 唯一自动来源：官方 `ggml-org/llama.cpp` 的 GitHub Releases（运行时查询 API，不硬编码任何标签/资产名）。
- 稳定通道默认启用；预发布通道需用户主动切换。
- 断言校验：下载 URL 必须为 `https` 且主机属于官方 GitHub 域（`github.com`、`objects.githubusercontent.com` 等）。
- GitHub 不可用时：显示可操作提示，并可“打开官方发布页”手动下载，再走“导入本地压缩包”同一流水线。
- 查询策略：发行列表带内存 + 磁盘缓存（`cache/`，含 ETag）；稳定/预发布通道共享同一份原始数据，60 秒内的重复查询不再请求；
  数据未变化时以 304 复用缓存（配置 GitHub 令牌时 304 不计入配额）。
- 频率上限（未登录 60 次/小时，按出口 IP）：解析 `X-RateLimit-Reset` / `Retry-After`，恢复时间前不发起请求；
  有缓存则回退缓存并标注缓存/恢复时间，无缓存则给出带恢复时间的可操作错误；
  启动自动检查按“检查间隔”节流，间隔内重启不重复请求；设置页可选配置 GitHub 令牌（5000 次/小时）。

## 2. 资产筛选（AssetSelector）

对每个发行版本：

1. 仅保留 Windows x64 的 `.zip`（排除 macOS/arm64/source 等）；
2. 按文件名分类后端：CUDA（含 `cu12.4` 等主次版本号）、Vulkan、SYCL、ROCm/HIP、OpenVINO、CPU（`cpu`/`avx*`）；
   无法识别时标记“未识别构建类型，请查看发行说明”，不擅自按 NVIDIA 选包；
3. `cudart-*` 识别为“运行时辅助包”，不能替代主程序包；它是 CUDA 主包的配套 DLL，安装主包成功后可一并安装（见 2.1）；
4. 推荐项仅为排序建议（本机已探测后端优先，其次 CUDA > Vulkan > SYCL > ROCm > CPU > 未识别），
   界面始终展示全部候选与其依据，由用户确认。

### 2.1 CUDA 运行时辅助包（cudart）配套安装

- 安装官方 CUDA 主程序包成功后，自动在同一发行版中匹配 cudart 辅助包并弹确认框“是否一并下载安装”；
  匹配只做可靠判断：CUDA 版本号完全一致优先 → 同主版本且唯一 → 主包未标注版本时仅有一个辅助包，其余不猜测；
- 安装过程复用主程序同一套流水线：官方来源域名校验、SHA-256（官方 digest 存在时）、ZIP 安全检查；
  解压后仅把其中的 `*.dll` 复制到该版本的 `llama-server.exe` 所在目录（子目录 DLL 会扁平化），不改默认指针、不动其他版本；
- 安装成功后自动重新探测该版本能力（主包在缺少 cudart 时可能探测不到 GPU 设备，重探测会刷新后端标签）；
- 跳过提示后可在“版本管理 → 已安装版本 → 安装运行时辅助包…”，对选中版本重新补装（需先加载发行列表）；
- 每次安装写入 `UpdateOperations`（`Kind=RuntimePack`）；绝不自动安装 NVIDIA 驱动。

## 3. 流水线与阶段

```
Checking -> Available -> Downloading -> Verifying -> Extracting -> Probing -> ReadyToSwitch -> Active
（另有 Cancelled / Failed / RolledBack / NotAvailable）
```

1. **下载**：流式写盘 + 增量 SHA-256，进度显示字节/总字节（未知时为不确定进度）与速度；支持取消，
   取消或失败会清理 `.part` 临时文件；服务端返回 HTML 错误页会被识别并拒绝。
2. **校验**：优先与 GitHub 资产 `digest`（`sha256:...`）比对；缺失 digest 时只记录本地指纹并在记录与 UI 中
   明确标注“非来源校验”。不匹配 → 失败，不安装（文件保留在下载目录供检查）。
3. **解压**：写入 `.staging-*` 目录；拒绝绝对路径、`..` 穿越、符号链接/重解析点、超限展开与异常压缩比（压缩炸弹）。
4. **探测**：在 staging 中查找 `llama-server.exe` 并执行完整能力探测；失败则清理 staging 并拒绝注册。
5. **注册**：移动到 `runtimes/llama.cpp/<版本>-<哈希前缀>` 独立目录，写入安装记录（版本、资产、SHA-256、
   探测结果、后端标签、来源类型）与 `manifests/installations.json`（原子写 + `.bak` 备份）。
6. **切换**：数据库默认指针 + 清单指针同步更新；切换前记录上一默认版本用于回滚。

## 4. 保护与回滚

- 正在使用的二进制目录不会被覆盖：新版本总是安装到新目录。
- 运行中的实例继续使用各自启动时绑定的版本；切换默认不影响它们，配置迁移由用户手动完成（编辑器会重新校验参数兼容性）。
- “回滚到上一默认版本”只需改指针，不迁移、不杀进程。
- 删除旧版本前校验：非默认、未被任何配置引用、未被运行中实例使用；删除文件仅允许发生在 runtimes 目录之内。
- 每次检查/下载/安装/切换/回滚/清理都写入 `UpdateOperations`（阶段、错误、哈希、目录、时间）。

## 5. 手动导入

- 支持导入官方或第三方 zip，但必须显式声明来源（默认按非官方处理并在记录中标注）。
- 手动导入不能绕过任何安全检查：路径/链接/体积限制、能力探测与独立目录安装完全相同。
