# LlamaLauncher 用户手册

## 1. 安装与启动

### 便携版
解压 zip 后直接运行 `LlamaLauncher.exe`。所有应用文件（`data/` 数据库、`logs/` 日志、`downloads/`、`runtimes/` 版本、`manifests/`、`backups/`、`exports/`）默认保存在程序根目录下。
从旧版本升级时，首次启动会自动把 `%AppData%\LlamaLauncher`（或旧便携布局 `exe\data`）中的现有数据迁移到程序目录，并改写数据库与安装清单中的绝对路径。

### 安装版
运行 `LlamaLauncher-Setup-x.y.z-x64.exe`。默认按用户安装，无需管理员权限；可选择安装路径与是否创建桌面快捷方式。
数据默认位于程序根目录；若安装到只读目录（如 Program Files），应用会自动回退使用 `%AppData%\LlamaLauncher` 并在启动时提示，也可在“设置”页指定其他数据目录。卸载不会删除数据目录内容。

> 本应用不包含也不下载 GGUF 模型；llama.cpp 二进制由你选择来自官方 Releases 的下载，或本机已有副本。

## 2. 第一次使用（推荐流程）

1. **准备 llama.cpp 程序**
   - 方式 A（推荐）：打开“版本管理”页 → 选择稳定通道 → “检查更新” → 在资产列表中选择与硬件匹配的包
     （每个资产的构建类型、CUDA 版本、大小、来源都会标注；推荐项仅为建议）→ “下载并安装所选资产”。
   - 方式 B：已自行下载官方 zip → “导入本地压缩包”（需勾选或声明来源）。
   - 方式 C：使用本机已有的 `llama-server.exe`：在“启动配置”页新建配置时选择“选择其他 exe…”。
   - 安装/导入后应用会执行能力探测（`--version` / `--help` / `--list-devices`），并把结果缓存为“能力快照”。
2. **添加模型**：“模型库”页 → “添加 GGUF 文件”或“扫描目录”。模型文件只被登记与读取元数据（文件头区域），不会被复制或删除；
   移除登记不会删除磁盘文件。
3. **创建启动配置**：“启动配置”页 → “新建配置”。参数面板只启用当前程序能力快照确认支持的参数；
   不支持的关键参数会阻止保存与启动，不会被静默忽略。
4. **启动实例**：“服务实例”页 → “新建实例”（选择配置）→ “启动”。等待状态从“加载模型中”变为“运行中”。
5. **开始聊天**：“内置聊天”页 → 选择运行中的实例 → 输入消息（Ctrl+Enter 发送）。

## 3. 各页面速览

| 页面 | 主要功能 |
| --- | --- |
| 概览 | 运行统计、默认版本、系统资源（CPU/内存，GPU 指标可用时显示来源）、最近模型与失败记录 |
| 服务实例 | 多实例启停/重启/强制结束、API 地址复制、API 连通测试、诊断包导出、详情（脱敏命令行） |
| 模型库 | 添加/扫描/失效检测、GGUF 元数据（架构/量化/上下文等，未知字段显示“未知”）、别名/标签/备注 |
| 启动配置 | 配置 CRUD、复制/导入/导出（JSON，默认不含秘密）、能力校验与命令预览（脱敏）、预设 |
| 内置聊天 | 会话管理、真实 SSE 流式输出、停止生成、系统提示词与采样参数、Markdown 与代码块复制 |
| 性能基准 | 对运行中实例流式测速：提示处理/生成速度、首 token 延迟、总耗时；多档提示长度、预热/重复/冷却、统计与历史、Markdown/JSON 报告 |
| 硬件与后端 | 系统信息、显示适配器（WMI）与“此二进制的实际推理设备”（--list-devices）分开显示 |
| 版本管理 | 检查更新、资产筛选（分类标注）、下载/取消/校验、独立目录安装、切换默认、回滚、清理、导入本地包 |
| 日志与诊断 | 应用日志与每实例 stdout/stderr（滚动+脱敏）、搜索/复制、导出诊断包 |
| 启动历史 | 每次启动的 PID、退出码、最终状态、失败阶段、脱敏命令行与错误摘要 |
| 设置 | 主题、托盘与关闭行为、数据目录与便携模式、资源采样、日志保留、更新通道与检查间隔、API Key、可选 GitHub 令牌、备份恢复 |

## 4. 聊天

- **发送**：`Ctrl+Enter`；`Enter` 为换行。生成中可随时“停止生成”，已生成内容会以“已中断”状态保存。
- **会话管理**：左侧列表支持按标题搜索；可新建、重命名、清空消息、删除会话，并可把整个会话导出为 Markdown 文件。
- **消息操作**：每条消息可“复制”原文（Markdown）或“删除”；最后一条助手回复可“重新生成”（删除该回复后基于原用户消息重跑，失败/中断的回复同样可重试）。
- **输入区**：显示已输入字符数；生成时右侧显示“停止生成”与实时耗时，空闲时仅显示“发送”。
- **消息区**：用户消息靠右（浅蓝色气泡）、助手消息靠左（灰色气泡），带时间与状态标记；生成中自动跟随滚动，手动上翻后暂停跟随并出现“↓ 回到底部 / ↓ 有新内容”浮动按钮。
- **连接状态**：标题下显示目标实例的连接状态；无就绪实例时可一键“去启动实例”，也可用“测试对话”直接验证对话端点（独立于 `/health`）。
- **参数**：右侧参数面板（“参数面板”按钮展开）。可设置系统提示词、temperature、top_p、top_k、min_p、repeat_penalty、seed、
  max tokens 与停止序列；“重置默认”恢复默认采样参数（不影响系统提示词）。
- **Markdown**：标题、列表、引用、表格、行内代码与代码块均按安全方式渲染（不执行 HTML/脚本）；
  代码块右上角提供“复制代码”，外链在系统浏览器中打开。
- **历史**：全部消息持久化到 SQLite；应用异常退出后，未完成的流式消息会在下次启动时标记为“已中断”。

## 5. 多实例

- 可同时运行多个实例（各自端口、日志、历史、健康检查相互独立）。
- 端口在启动前做占用预检查，启动后通过 `/health` 确认就绪；“加载中”与“失败”是不同状态。
- 局域网监听（host 改为 `0.0.0.0` 或局域网 IP）属于高风险操作：启动前会弹出风险确认，要求已配置 API Key，
  且当前二进制必须支持 `--api-key`。API Key 不提供传输加密。

## 6. 更新与回滚

- 默认稳定通道；预发布需手动把通道切换为“预发布”。
- 启动时的自动检查按“设置 → llama.cpp 更新 → 检查间隔（小时）”节流：间隔内重启应用不会重复请求 GitHub。
- 发行列表带本地缓存：GitHub 请求频率达上限（未登录每小时 60 次，按出口 IP 计算）或离线时，
  应用回退显示最近一次成功获取的列表并标注缓存时间与限额恢复时间，恢复时间前不再请求；
  需要更高配额（共享网络或频繁检查）可在同一设置卡片配置可选 GitHub 令牌（DPAPI 加密存储，仅只读查询，5000 次/小时）。
- 每个版本安装到 `runtimes/llama.cpp/<版本-指纹>` 独立目录，不会覆盖正在使用的版本。
- **本地版本发现**：应用启动时会自动扫描版本目录（`runtimes/llama.cpp`），把手动拷入的已解压版本探测并登记到“已安装版本”列表；
  也可在版本管理页点击“扫描本地版本”随时重扫。目录建议沿用 `<版本标签>-<指纹>` 命名（如 `b10618-91b16d71`），
  此时版本标签优先采用目录名；没有默认版本时，首个探测可用的版本会自动设为默认。
- “设为默认”会记录上一个默认版本；任何时刻可“回滚到上一默认版本”。运行中的实例不受切换影响。
- 官方发布未提供 SHA-256 digest 时，应用只记录“本地指纹”，并在界面明确标注不代表可信来源校验。

## 7. 数据与备份

- 数据目录：默认程序根目录（`data/` 数据库、`logs/` 日志、`runtimes/` 版本、`manifests/` 清单、`backups/` 备份、`exports/` 导出）；“设置”页可查看当前实际目录、切换为 `%AppData%` 或自定义目录。
- 路径设置：“设置”页可单独修改 **llama.cpp 版本目录、更新下载目录、模型目录**（“更改…”选择目录，“恢复默认”回到数据目录下默认路径，保存后立即生效）。
  版本目录变更只影响之后的新安装与本地版本发现，已安装版本仍按原路径正常使用与删除；下载目录用于更新包的临时下载；模型目录是模型库“添加文件/扫描目录”的默认起始目录。
- “设置”页可一键在线备份数据库；恢复前会自动备份当前数据库，恢复失败自动回滚。恢复后需重启应用。
- 配置档案导出为版本化 JSON（默认不含秘密引用，任何情况下都不含密钥本体）。

## 8. 常用快捷键与托盘

- `Ctrl+Enter`：发送消息；“停止生成”按钮可中断当前流式响应。
- 关闭窗口的默认行为是**最小化到托盘**（可在设置中改为直接退出）；托盘菜单可显示主窗口、启停实例、退出。
- 退出应用时会先停止由本应用启动的服务进程（不遗留孤儿进程），并提供确认。

## 9. 决策模型实验室（简版入口）

左侧导航「决策模型实验室」提供五个子页：**模型调试**（单次调用 `/v1/systemone`）、
**工作流设计与调试**（画布编辑 + 运行/单步/断点/轨迹/节点详情）、**测试用例**（断言与模拟响应）、
**批量测试**（受控并发与统计导出）、**运行历史**（详情、比较、复制为新用例、导出诊断）。

最小上手：在「服务实例」启动一个决策模型实例 → 实验室「模型调试」选择实例并运行 →
「工作流设计与调试」拖入节点/连线/配置后运行 → 「测试用例」配置断言并用模拟响应回归。

完整说明（工作流文件格式、节点清单、表达式与模板语法、调试技巧、限制清单）见
[决策模型实验室文档](DECISION_LAB.md)。

## 10. 性能基准

左侧导航「性能基准」用标准化的请求测量模型的推理速度，适合比较不同模型、量化格式、启动参数或硬件的表现。

- **准备**：先选择状态为“运行中”的实例（实例由“服务实例”页启动）。测量期间该实例的推理会被占用。
- **配置**：
  - 提示长度：以逗号分隔多个档位（16–131072 tokens，最多 6 档），如 `512, 2048`；实际 token 数以服务端统计为准；
  - 生成长度：每次请求生成的最大 token 数（1–4096）；
  - 重复 / 预热：每个档位先执行“预热”（不计入统计，消除首次加载与冷缓存影响）再重复测量；
  - 冷却：样本之间的等待秒数（为散热或后台任务留出间隔）；
  - 预设按钮：快速 512 / 标准 512+2048 / 长上下文 2048+4096。
- **测量方式**：通过 llama-server 的 `/completion` 端点流式请求；每次禁用提示缓存（`cache_prompt=false`）并附加随机前缀，
  保证每次都是真实的提示处理（prefill，不会被 KV 缓存“虚高”）；采样为贪心（temperature=0）。
  速度取自服务端 timings；首 token 延迟与总耗时由客户端实测。运行中实时显示进度，可随时“取消”（保留已完成样本）。
- **结果**：按档位显示“均值 ± 标准差”（不含预热与失败样本）、平均实际提示 token 数以及成功/失败样本数；
  下方为逐样本明细（含预热标记与错误原因）。连续 2 次调用失败会自动提前中止并说明原因。
- **历史与导出**：每次运行自动保存到历史记录（SQLite）；可查看详情、删除、复制 Markdown 报告或导出 JSON
  （含配置快照与全部样本），便于归档与横向对比。
