# llama.cpp 兼容策略

llama.cpp 是独立更新的外部程序：不同版本的 CLI 参数、取值与 API 细节都可能变化。
LlamaLauncher 的原则是**运行时探测、按能力生成参数、不静默忽略**。

## 1. 能力快照（Capability Snapshot）

对每一套 `llama-server.exe` 分别执行并缓存：

| 探测命令 | 超时 | 用途 |
| --- | --- | --- |
| `--version` | 15 秒 | 版本标签与构建信息 |
| `--help` | 25 秒 | 解析支持的参数、别名与取值提示 |
| `--list-devices` | 25 秒 | 该二进制实际可用的推理设备 |

结果包含：原始输出（stdout/stderr 全文）、解析出的参数表、设备表、每条探测的退出码/耗时/超时状态与警告。
缓存键为「可执行文件绝对路径 + 文件指纹（大小 + 最后写入时间）」；文件变化或用户手动“重新探测”即失效。

## 2. 帮助文本解析

解析器（`HelpTextParser`）对版本差异做了容错：

- 支持 `-c, --ctx-size <N>` 与旧式 `-c N, --ctx-size N` 两种排版；
- 识别 `<必填>`、`[可选|取值]`、`{枚举}` 与 `N`/`MODE` 等占位符形式；
- 分节标题、空行、垃圾行不影响其他条目；无法识别的行只忽略并保留原文，不抛异常；
- 通过内置“参数目录”把多种写法（`-c` 与 `--ctx-size` 等）归一到同一规范名。

## 3. 参数生成规则

1. 命令行始终由结构化选项生成 argv（`ArgumentList` 逐个传参，绝不拼字符串过 shell）。
2. 每个 UI 参数先查能力快照：
   - 快照确认支持 → 使用快照中出现的 flag（优先参数目录里的首选长格式）；
   - 快照明确不含该参数 → **阻止启动**并指出参数名（UI 面板同时禁用该字段）；
   - 能力快照缺失 → 界面提示先执行探测；不猜测支持情况。
3. 取值合法性按帮助文本判断，例如 `--n-gpu-layers` 是否允许 `auto`/`all`；
   `--flash-attn` 是“开关”（旧版）还是 `[on|off|auto]`（新版）由快照决定：
   - 开关形式下选择“关闭”→ 警告并忽略（无法表达）；“自动”→ 警告并按“开启”处理（等效）；
   - 取值形式下按帮助文本校验取值。
4. 高级额外参数：按 Windows 命令行规则解析；与 UI 管理的 flag 冲突时默认阻止保存，
   除非显式启用“允许高级参数覆盖”（执行时以额外参数为准，界面会给出警告）。
5. API Key 仅当快照确认支持 `--api-key` 时可用；命令预览、日志与历史中一律掩码为 `******`。

## 4. 设备判定（三层区分）

| 层级 | 来源 | 显示位置 |
| --- | --- | --- |
| 系统显示适配器 | WMI `Win32_VideoController` | 硬件页左侧（明确标注“不代表 llama.cpp 可用设备”，AdapterRAM 可能不准确） |
| 构建后端迹象 | 资产名/依赖/版本输出 | 版本管理页的资产分类（仅作为标签） |
| 实际可用设备 | 该二进制的 `--list-devices` 输出 | 硬件页右侧“实际推理设备” |

GPU 利用率/显存指标仅来自可验证来源（如 nvidia-smi），不可获取时显示“—”而不是估算值。

## 5. 未知版本与新参数

- 新参数（未内置到分类目录）会以“未知参数”形式展示在帮助解析结果中，可在高级参数中使用，
  界面会标记“未在当前版本帮助中确认”。
- 探测失败（两条命令都失败）时按“不可用”处理，不允许启动，并保留原始输出供诊断。
- 任何解析器都能容忍无法识别的格式：不因某个版本的排版变化而崩溃。
