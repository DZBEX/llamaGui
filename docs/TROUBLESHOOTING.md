# LlamaLauncher 故障排查

> 原则：应用会给出错误类别、用户可见摘要与建议；日志与诊断包保留技术细节（已脱敏）。
> 所有“可能原因”均为提示，不把猜测当结论。

## 1. 启动类问题

### 实例状态停在“加载模型中”
- 大模型首次加载需要时间；`/health` 在加载期间返回非成功状态属正常。
- 查看“服务实例”→“查看日志”中的 stderr：如出现 `failed to load model`、`out of memory`、`unknown argument` 等，
  按对应条目处理。
- 加载完成后仍未就绪：检查端口监听的日志行；若程序因参数错误立即退出，实例会变为“失败/异常退出”，详情中会给出退出码与 stderr 摘要。

### 启动前校验失败（不会启动）
常见原因与处理：

| 信息 | 原因 | 处理 |
| --- | --- | --- |
| 端口 N 已被占用 | 其他程序或实例占用了端口 | 更换端口（应用不会抢占他人端口） |
| 当前 llama.cpp 版本不支持参数 X | 参数不在该版本 `--help` 中 | 在参数面板移除该设置，或换用支持该参数的版本 |
| 高级参数与参数面板冲突 | 额外参数重复指定了 UI 管理的 flag | 删除冲突参数，或启用“允许高级参数覆盖” |
| 模型文件不存在 / 文件头不是 GGUF | 文件被移动、损坏或不是 GGUF | 在模型库重新定位或更换文件 |
| 局域网监听需要…API Key | 未启用或未配置密钥 | 启用 API Key 并在设置中配置；确认二进制支持 `--api-key` |
| 能力探测失败 | 二进制不完整/缺 DLL/不是有效程序 | 在“硬件与后端”页查看原始探测输出；重新下载或更换程序 |

### 从另一台电脑拷来后启动失败

- 整个程序目录一起复制时，应用会在首次启动自动改写数据库与安装清单中的旧绝对路径；如果只复制了
  `LlamaLauncher.exe` 和少量 DLL，请补齐 `data\`、`runtimes\` 与发布目录中的其他文件。
- 提示“未找到可用的 llama-server.exe 程序路径（原路径可能已失效）”时，应用会先尝试同版本、当前默认与任一可用版本；
  若本机没有可用版本，请在“版本管理”扫描/导入完整 llama.cpp 包，或在“启动配置”重新选择程序。
- 若 `llama-server.exe` 能看见但探测失败，检查版本目录是否只有单个 exe。官方新版包通常还需要同目录的
  `ggml*.dll`、`llama*.dll` 等运行库；请复制完整发行包目录，而不是只复制可执行文件。
- 模型文件不在程序目录内，不会随程序自动搬家；请在新电脑放到相同路径或在“模型库”重新选择。

## 2. GPU / 后端问题

- **界面显示“未探测到 GPU 推理设备”**：说明该 `llama-server.exe` 的 `--list-devices` 没有列出 GPU（CPU-only 构建、
  缺少对应后端运行库、或驱动不支持）。应用不会因为机器有 NVIDIA 显卡就假定 CUDA 构建可用。
- **CUDA 包启动报缺少 DLL**：官方 CUDA 包依赖 `cudart` 运行时包与 NVIDIA 驱动。安装官方 CUDA 主包后应用会自动匹配
  同发行版的 `cudart-llama-*` 包并询问是否一并安装；若此前点了“跳过”，可在“版本管理 → 已安装版本 → 安装运行时辅助包…”补装。
  仍缺 DLL 时请确认驱动版本满足发行说明要求；应用不安装驱动。
- **Vulkan/Intel 等设备**：以 `--list-devices` 的实际输出为准；资源页中的 “GPU 利用率” 仅当来源可用
  （如 nvidia-smi）时显示，其余显示“—”。
- **显存不足（out of memory）**：降低 `--n-gpu-layers`、上下文长度、批大小或并行槽位；应用只给提示，不会自动修改你的配置。

## 3. 聊天/API 问题

| 现象 | 类别 | 处理 |
| --- | --- | --- |
| 连接被拒绝 | Connection | 实例未运行或端口错误；先在“服务实例”页确认“运行中” |
| 401/403 | Unauthorized | 服务启用了 API Key，但密钥不一致；在设置中更新密钥并重启实例 |
| 404 | NotFound | 该版本没有对应端点；用“API 测试”确认可用端点 |
| 429 | RateLimited | 请求过快；等待后重试 |
| 5xx | ServerError | 服务内部错误；查看实例日志 |
| 流在结束标记前中断 | Interrupted | 网络/服务中断；已收到内容按“已中断”保存，可重试 |
| 连续无效数据帧 | Protocol | 服务版本与预期的 SSE 格式不兼容；请记录诊断包 |

## 4. 更新问题

- **无法连接 GitHub**：离线环境属正常；可用“打开官方发布页”手动下载后“导入本地压缩包”。
- **GitHub API 请求频率达上限**：未登录请求的配额为每小时 60 次（按出口 IP 计算）。应用已按“检查间隔”节流启动检查，
  并缓存发行列表：命中上限期间会直接显示最近一次成功获取的缓存数据（界面标注获取时间与限额恢复时间），
  且在恢复时间前不再发起请求；提示中的恢复时间来自 GitHub 响应头。共享出口 IP（公司网络、VPN）或频繁检查时，
  可在“设置 → llama.cpp 更新”配置可选 GitHub 令牌（只读公共仓库、无需勾选任何权限）：5000 次/小时，
  且数据未变化（304）时不计入配额。也可以随时“打开官方发布页”手动下载后“导入本地压缩包”。
- **离线或网络受限**：有缓存时显示上次获取的发行列表并标注缓存时间；无缓存时给出“打开官方发布页 / 导入本地压缩包”的提示。
- **SHA-256 校验失败**：下载内容与官方 digest 不一致，已拒绝安装；删除下载目录中的残留文件后重试。
- **解压被拒绝（路径穿越/符号链接/压缩炸弹）**：压缩包不安全或已损坏，请重新下载官方包。
- **安装后能力验证失败**：该包无法在本机运行（缺 DLL/架构不匹配等）；版本不会注册，当前默认版本不受影响。
- **新的默认版本启动失败**：使用“回滚到上一默认版本”一键恢复。

## 5. 数据与日志问题

- **数据库损坏/无法打开**：启动时会阻止进入并给出提示；从 `backups/` 选择备份恢复（设置页），或重命名数据库文件重新建库。
- **日志写入失败**：界面出现告警行，应用继续运行；检查日志目录磁盘空间与权限。
- **诊断包内容**：包含应用/实例日志、设置、安装与实例信息；API Key、令牌等敏感值会被脱敏，
  默认还会把用户目录替换为 `<user-path>`。诊断包不包含聊天数据库与密钥明文。

## 6. 如何反馈问题

“日志与诊断”页或“设置”页导出诊断包（zip），附上：
1. 复现步骤与期望行为；
2. 实例状态与错误摘要（实例页/启动历史页）；
3. 诊断包（如涉及敏感路径可先自行检查）。
